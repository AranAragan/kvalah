# Kvalah Compute · восстановление передачи и повторов раунда

## Что установлено на R60

Три попытки раунда завершились с двумя принятыми обновлениями при quorum 3. Следующие попытки вычислили результат заново. Для устройства 2 медиана от lease до принятия составила 149,95 с при медиане вычислений 4,50 с и загрузки модели 14,97 с. Эти интервалы включают ожидания. По экспортированным данным время между стадиями нельзя отнести к конкретной операции протокола или Governor. Полный раунд занимал медиану 150,68 с, p95 541,80 с. Агрегация занимала медиану 63 мс.

## Контракты для реализации

1. **Возобновляемая передача.** Согласовывать возможность между Coordinator и Worker. Хранить принятые байтовые диапазоны под ключом upload, привязанным к подписи, владельцу, immutable assignment и полному SHA-256. По запросу возвращать подтверждённые диапазоны, ограничивать размер частичного хранилища, проверять размер и контрольную сумму каждого фрагмента. Проверять полный SHA-256 перед публикацией в CAS и переходом в uploaded. Возобновление той же попытки сохраняет lease gate и учёт трафика. Для старых клиентов остаётся текущий PUT.
2. **Восстановление outbox.** Текущий Worker fsync-ит payload и метаданные и использует idempotency key. Ввести durable transitions и сохранять неопределённое подтверждение отдельно от terminal state. При reconnect сначала сверять terminal status по update ID или idempotency key, включая гонку потери commit-ответа и локального lease expiry. Coordinator аутентифицирует чтение результата владельцем и хранит однозначный terminal статус. GC сохраняет unresolved-записи до сверки и резервирует место в пределах квоты.
3. **Повторное использование вычисленного обновления.** Переносить только проверенный Coordinator артефакт внутри той же логической задачи при повторе с идентичным родителем. Проверять experiment_id, round index, slot, config, dataset/rows SHA, mask, число supervised tokens, frozen A, optimizer, model variant digest, происхождение, полномочия устройства и payload schema. Фиксировать ссылку на исходное решение об acceptance транзакционно под уникальным ключом experiment/round/attempt/slot. Сохранять один вклад слота, quorum с независимыми устройствами, идентичный протокол FedAvg и правила отзыва. Для просроченных, невалидированных, отозванных и частичных артефактов действуют текущие запреты.
4. **Резидентная базовая модель.** Реализовать ограниченный кэш sidecar по ключу backend, model digest, архитектуре, схеме, dtype и устройству. Для новой задачи применять точный A/B родителя, сбрасывать optimizer и RNG согласно конфигу. Пауза, нехватка памяти, foreground AI, отзыв, смена модели и выключение участия освобождают память по правилам Governor. Кэш не ослабляет проверки актуальности весов и термобюджета. Разделить измерения cold load, cache hit, evict, adapter reset и выполнения задачи.

## Приёмка

| Сбой | Обязательный результат |
|---|---|
| Клиент прерван посреди передачи | Подтверждённые фрагменты переживают рестарт. Полный digest сходится. CAS и quota согласованы. |
| Coordinator упал после записи CAS или DB | Повтор commit отвечает тем же результатом, двойной вес исключён. |
| ACK потерян, lease истёк, ответ уже принят | Клиент сверяет terminal state без повторного обучения и без предоставления права записи после expiry. |
| Открыт повтор с тем же parent и исходным валидным результатом | Координатор переносит только подходящие слоты. Final B совпадает с контрольной агрегацией этих обновлений. |
| Изменены родитель, маска, variant, устройство отозвано или уже учтено | Перенос запрещён. Состояние слота остаётся корректным. |
| Новый task после прогретого | Контрольная пара fresh и resident при одинаковом входе и backend даёт B в заранее установленном допуске. Frozen A и выходы остаются проверяемыми. |
| Включён foreground AI или Governor запрещает продолжение | GPU-кэш освобождается в заданный предел, lease и сохранённый outbox переходят в допустимое состояние. |

Отдельно измерять байты повторных передач и partial GC, время declare/upload/commit, очередь, Governor wait, время загрузки, GPU/RAM, количество исключённых и сохранённых вычислений. Сравнить с R60 на одинаковой нагрузке и причинно различимых вводимых сбоях. Test сохраняется для независимой оценки после фиксации протокола.
